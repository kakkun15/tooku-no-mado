部屋

部屋を作ると4文字の番号ができます。友だちがその番号で入ると、同じ景色の中にアバターが並び、チャットできます。曲はそれぞれの端末で流れます。

チャットは画面の左下の欄から送れます。

つながり方の説明

部屋を作ると、4文字の番号（合言葉）ができます。友だちがその番号を入れると、おたがいのブラウザが直接つながります。

直接つながるまでの「待ち合わせ」だけ、無料の案内所（PeerJS のサーバー）を使います。つながったあとは、アバターの場所や話したことは、案内所を通らずに相手へ届きます。回線によって直接つながれないときは、PeerJS の中継所を通ります（そのときも中身は暗号化されています）。

話したことはどこにも保存されません。部屋を出ると消えます。

気をつけること：直接つながるしくみなので、同じ部屋の人どうしには、おたがいの IP アドレス（ネット上の住所のようなもの）が伝わります。番号は知っている人とだけ共有してください。

部屋を作った人（ホスト）が画面を閉じたり、部屋を出たりすると、部屋はなくなります。

  • 通信：WebRTC のデータチャネル。中身は DTLS で暗号化されます。ライブラリは PeerJS 1.5.5（MIT ライセンス、unpkg から読み込み）。部屋の機能を開くまでは読み込みません。
  • シグナリング：接続情報（SDP と ICE 候補）の交換に、PeerJS の公開サーバー 0.peerjs.com を使います。ホストは部屋の番号から決まる ID（tooku-no-mado-XXXX）で登録し、ゲストはその ID へ接続を申し込みます。
  • NAT 越え：PeerJS の既定の設定どおり、STUN（stun.l.google.com）で直接の経路を探し、だめなときは PeerJS の TURN サーバーで中継します。
  • 形：スター型。ホストが全員とつながり、届いたものをほかの人へ配ります。最大 8 人。ホストが抜けると部屋は終わります。
  • 送るもの：アバターの見た目と位置（画面に対する割合 0〜1）、チャット（80文字まで）、ホストの景色・天気・時刻・乱数の種（同じ景色を描くため）。曲や音は送りません。
  • 受け取ったものの扱い：ホストは送り主を接続相手で見分け、値の種類と長さを確かめてから配ります。送る回数にも上限があります。画面には文字としてだけ表示します（HTML として解釈しません）。
  • IP アドレス：ICE 候補にはグローバル IP アドレスが含まれるため、同じ部屋の人には見えます。会話の記録は各端末のメモリの中だけで、保存も送信もしません。
